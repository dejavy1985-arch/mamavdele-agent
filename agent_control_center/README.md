# agent_control_center (Клоп)

Личный центр управления агентами из одного Telegram-чата, по возможностям Jarvis,
адаптированный под единый чат. Вы пишете задачу обычным текстом; Клоп определяет
проект, агент этого проекта **выполняет** задачу, а статус и результат приходят в
тот же чат ответом на ваше сообщение.

Проект лежит отдельной папкой и не меняет действующего агента `mamavdele-agent`.

## Как проходит задача

1. Сообщение в Telegram. Чужие отправители игнорируются (allowlist).
2. Проверка границ: публикации, переписка с клиентами, платежи, смена токенов агентам
   не передаются.
3. Выбор проекта по тексту; если неясно, Клоп спрашивает; явно: `/to <id> <задача>`.
4. Опасная задача (удалить, перезаписать, выкатить) ждёт `/confirm` или `/reject`.
5. Задача встаёт в очередь, в чат уходит «📥 Принято» с номером и местом в очереди.
6. Исполнитель в фоне запускает агента проекта в его папке, в песочнице: агент видит
   только свою папку, получает только свои секреты, сеть только по разрешению.
7. В тот же чат приходит «✅ выполнил» с ответом агента, или «❌ не выполнена» с
   причиной, или «⏹ остановлена». Длинный ответ делится на части, целиком: `/result <id>`.

## Команды в чате

`/projects`, `/status`, `/status <id>`, `/queue`, `/history`, `/result <id>`,
`/cancel <id>`, `/confirm <id>`, `/reject <id>`, `/to <id проекта> <задача>`, `/log`,
`/help`.

## Что работает и проверено

Автотесты: 126, все проходят на Python 3.10, 3.11, 3.12, 3.13 (Linux). Сторонние
пакеты не нужны.

- Реальное выполнение задачи агентом и возврат статуса и результата в тот же чат:
  сквозной тест через Telegram (подменена только сеть Telegram) на тестовом агенте.
- Очередь: задачи одного проекта строго по порядку, разных проектов параллельно.
- Отмена работающего агента, таймаут, понятные ошибки.
- Изоляция процессов песочницей bubblewrap: агент не читает соседний домик ни по
  абсолютному пути, ни через `..`; сеть отключается; токен бота и чужие ключи агенту
  не передаются.
- Восстановление после перезапуска: очередь продолжается, о прерванных задачах
  приходит сообщение в их чат, ожидающие подтверждения сохраняются.
- Адаптер Claude Code: своя сессия, память и ключ у каждого домика, продолжение
  разговора через `--resume` (проверено на поддельной программе с форматом ответа
  настоящего Claude Code).

Полный перечень функций Jarvis со статусами (полностью, частично, отсутствует,
только с внешним сервисом) и предлагаемым порядком: `RESEARCH_JARVIS.md`.

## Что ещё не проверено вживую

- Настоящий Telegram: нужен токен бота на вашем сервере.
- Настоящий Claude Code: нужен ключ Anthropic в `secrets/agent.env` домика.
- Реальные проекты не подключены: `mamavdele-agent` в статусе `registered`.

## Домики сейчас

- `test-agent`: **тестовый** агент без ИИ, не реальный проект. Реально выполняет
  простые команды (переверни, посчитай слова, запомни, подожди, сломайся, прочитай),
  чтобы проверить весь путь.
- `mamavdele-agent`: реальный проект, не подключён (`registered`).
- `example-template`: образец манифеста для агента на Claude Code, не подключён.

## Проверить без Telegram

```bash
python3 -m acc.cli ask "тест: переверни привет"   # полный путь: агент выполняет задачу
python3 -m acc.cli demo                            # два временных домика, изоляция
python3 -m acc.cli doctor                          # самопроверка конфига и домиков
python3 -m acc.cli route "текст"                    # какой проект будет выбран
python3 -m acc.cli queue | history | recover
python3 tests/run_tests.py                          # все автотесты
```

`ask` печатает всё, что пришло бы в чат. `demo` показывает, что агент одного домика
не может прочитать секрет соседнего.

## Подключить агента

Проект это папка в `homes/` с `manifest.json`. Ядро менять не нужно. Типы агентов:
`process` (любая программа), `claude_code` (Claude Code), `manual` (только запись в
папку, выполнением не считается). Подробно: `ADDING_PROJECTS.md`.

## Где запускать

Основной путь: Linux-сервер (Beget VPS), см. `DEPLOY_SERVER.md`. Для проверки на
своём Windows есть `INSTALL_WINDOWS.md` (песочница bubblewrap там недоступна).

## Структура

`acc/` ядро: `dispatcher.py` (доступ, границы, маршрут, очередь, команды),
`worker.py` (фоновое выполнение и ответы в чат), `runner.py` (запуск агента,
песочница, окружение, Claude Code), `store_db.py` (SQLite), `telegram_bot.py`,
`cli.py`, `router.py`, `guardrails.py`, `paths.py`, `registry.py`.
`homes/` домики, `config/` настройки, `tests/` автотесты, `scripts/` запуск,
`deploy/` служба systemd. Архитектура: `ARCHITECTURE.md`.

Идеи взяты из Jarvis (Apache-2.0), claude-commander, pochi, hermes-agent (MIT);
код не копировался.
