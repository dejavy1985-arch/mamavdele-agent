# Как подключить проект (домик) без правки ядра

Проект это папка в `homes/` с файлом `manifest.json`. Реестр сам находит её,
маршрутизатор учитывает её ключевые слова, исполнитель запускает её агента, песочница
ограничивает его этой папкой. Код ядра (`acc/`) при этом не меняется.

## Быстро: командой

```
python3 -m acc.cli add-home my-project --title "Мой проект" --keywords "отчёт,выгрузка" --aliases "мойпро"
```

Создаст домик в статусе `registered` (заведён, но не подключён). Дальше выберите тип
агента в `manifest.json` и смените статус на `connected`.

## Типы агентов (поле `adapter.type`)

### `claude_code`: агент на Claude Code

```json
{
  "id": "my-project",
  "title": "Мой проект",
  "status": "connected",
  "keywords": ["отчёт", "выгрузка"],
  "aliases": ["мойпро"],
  "adapter": {
    "type": "claude_code",
    "permission_mode": "acceptEdits",
    "max_turns": 30,
    "timeout_sec": 1800,
    "sandbox": "required",
    "network": true,
    "continue_session": true
  }
}
```

- Ключ: одной строкой `ANTHROPIC_API_KEY=...` в `homes/my-project/secrets/agent.env`
  (папка `secrets` в git не попадает). Ключ получает только агент этого домика.
- Память проекта: файл `CLAUDE.md` в папке домика. HOME агента указывает в его
  папку, поэтому настройки и сессии Claude Code у каждого домика свои.
- `continue_session`: следующая задача продолжает разговор с агентом (`--resume`).
- Необязательные поля: `model`, `allowed_tools`, `disallowed_tools`,
  `append_system_prompt`, `bare`, `claude_bin`.

### `process`: любая программа-агент

```json
"adapter": {
  "type": "process",
  "command": ["{python}", "agent.py"],
  "timeout_sec": 600,
  "sandbox": "required",
  "network": false
}
```

Программа запускается в папке домика, текст задачи получает на вход (stdin), ответ
печатает (stdout). Код выхода 0 значит успех. `{python}` заменяется на текущий Python,
`{home}` на путь домика. Пример: `homes/test-agent/agent.py`.

### `manual`: только запись в папку

Поручение записывается в `inbox/tasks.jsonl` домика, агент не запускается. В чате
это честно показано как «только записана в папку, агент её не выполнял».

## Изоляция (поле `sandbox`)

- `required` (по умолчанию): агент запускается только в песочнице bubblewrap. Если
  её нет, задача не выполняется, в чат приходит причина. Для реальных агентов.
- `preferred`: без песочницы агент всё равно запустится, в ответе будет пометка.
  Так настроен тестовый агент.
- `off`: без песочницы.

В песочнице агент видит только системные папки (только чтение) и свою папку.
`network: false` отключает ему сеть. Переменные окружения собираются с нуля: токен
бота и секреты других домиков агенту недоступны.

## Статусы домика

- `registered`: заведён, но не подключён, задачи не выполняются.
- `connected`: подключён и выполняет задачи.
- `not_connected`, `paused`: временно недоступен или выключен.

Тестовые домики помечайте `"test": true`: в `/projects` они показываются как
тестовые и не выдаются за реальные проекты.

## Проверить, ничего не запуская в Telegram

```
python3 -m acc.cli doctor
python3 -m acc.cli route "сделай выгрузку"
python3 -m acc.cli ask --project my-project "проверочная задача"
```
