# Запуск на Linux-сервере (основной путь)

Центр будет жить на сервере, поэтому основной способ запуска Linux. Windows-скрипты
в `scripts/*.ps1` нужны только если захотите проверить проект на своём ПК.

## Важно про тариф Beget

Telegram-центр держит одно постоянно работающее соединение с Telegram (long
polling). Для этого нужен сервер, где разрешён постоянно запущенный процесс:

- **VPS (облачный сервер Beget)**: подходит. Работает служба systemd, центр
  поднимается сам после перезагрузки сервера и после падения.
- **Виртуальный хостинг Beget** (адреса вида `*.beget.tech`): там обычно нельзя
  держать постоянно работающий процесс. Для такого тарифа нужен другой способ связи
  с Telegram (webhook), он пока НЕ реализован. Ядро при этом переписывать не нужно,
  меняется только транспорт.

Уточните тариф, от этого зависит следующий шаг.

## Установка на VPS

1. Скопируйте папку `agent_control_center` на сервер, например в `~/agent_control_center`.
2. Проверка (бот не запускается, токен не нужен):
   ```bash
   cd ~/agent_control_center
   bash scripts/run_server.sh --check
   ```
   Должно быть `OK` в тестах и «Итог: конфиг и домики валидны».
3. Конфиг: скопируйте `config/control_center.example.json` в
   `config/control_center.json` и впишите свой Telegram user_id.
4. Токен (когда решите включить Telegram): одной строкой в
   `config/telegram_token.txt`, затем `chmod 600 config/telegram_token.txt`.
   Файл в git не попадает.
5. Пробный запуск: `bash scripts/run_server.sh` (остановить Ctrl+C). При неверном
   токене центр сразу скажет об этом и выйдет.
6. Постоянная работа: служба из `deploy/acc.service` (инструкция внутри файла).
   Журнал службы: `journalctl -u acc -f`.

## Что переживает перезапуск

Смещение сообщений Telegram, очередь поручений, статусы, история и ожидающие
подтверждения хранятся в `var/`. При старте центр сам подхватывает поручения,
прерванные на середине (`python3 -m acc.cli recover` делает то же вручную).
