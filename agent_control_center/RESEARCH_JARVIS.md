# Разбор Jarvis (coreybain/jarvis) для центра управления агентами

Изучено по исходному коду, не только по README. Клон репозитория, чтение
`README.md`, `CLAUDE.md`, `package.json`, схемы БД, роутеров tRPC, модулей
безопасности путей, очереди, удалённого транспорта и режимов разрешений.

## Что такое Jarvis (кратко)

Настольное приложение (Electron + React + TypeScript) для работы с кодинг-агентами
(Claude Code и Codex) из одного окна. Данные локально в SQLite (через Drizzle).
Лицензия **Apache-2.0** (разрешает свободное использование, идеи брать можно).
Собирается под Windows (`package:win`, есть `src/main/lib/platform/windows.ts`).

Важно про деньги и облако: часть функций завязана на сервис `jarvis.dev` и платную
подписку Pro/Max. Это подтверждается кодом: удалённый транспорт бьётся в
`https://jarvis.dev/api/agents/chat` и возвращает «usage limit reached», а README
прямо пишет, что автоматизации требуют подписки. Локальная работа со своими
ключами (BYOK) бесплатна при сборке из исходников.

Наш центр другой по природе: Jarvis это GUI, который сам запускает агентов на
вашей машине. Наш центр это Telegram-диспетчер, который маршрутизирует поручения
в домики проектов и держит изоляцию, статусы, историю и подтверждения. Поэтому из
Jarvis берём идеи и модель данных, а не архитектуру Electron.

## Как читал (файлы-источники)

- `src/main/lib/db/schema/index.ts` (модель данных: projects, chats, sub_chats, аккаунты);
- `src/main/lib/trpc/routers/` (claude, codex, agents, chats, plugins, skills, voice, terminal);
- `src/main/lib/git/security/path-validation.ts` и `secure-fs.ts` (изоляция путей);
- `src/renderer/features/agents/lib/queue-utils.ts` и `stores/message-queue-store.ts` (очередь);
- `src/renderer/features/agents/lib/remote-chat-transport.ts` (удалённый доступ через jarvis.dev);
- режим разрешений в `routers/claude.ts` (plan против bypassPermissions, canUseTool).

## Облачные и платные функции: честно и с локальными аналогами

- **Фоновые агенты Jarvis** это их облачные песочницы, доступны по подписке Pro/Max.
  Локальный аналог для вас без покупки сервера: центр работает на вашем включённом
  ПК, поручения стоят в очереди и выполняются локальным агентом. «Когда ноутбук
  закрыт» без облака не получится, это честное ограничение.
- **Доступ с телефона (PWA Jarvis)** завязан на аккаунт jarvis.dev. Наш локальный
  аналог проще и бесплатен: Telegram-бот на вашем ПК, вы пишете ему с телефона.
- **Автоматизации (GitHub/Linear/Slack)** требуют подписки. Локальный аналог позже:
  на вашем ПК слушать события и класть поручение в очередь домика. На этапе 1 не
  делаем, чтобы не трогать действующие агенты.
- **Программный API** это облако jarvis.dev, платно. Нам не нужен: точка входа это
  ваш Telegram.
- **Голосовой ввод** работает со своим ключом OpenAI Whisper (BYOK) или по подписке.

## Что я реально добавил в проект в этот заход (проверено тестами)

Ничего не объявляю готовым сверх проверенного. Сейчас в проекте работает и покрыто
тестами (всего 67 тестов, все проходят):

- SQLite-хранилище `acc/store_db.py`: очередь поручений, статусы, история событий,
  дескриптор сессии проекта, восстановление после перезапуска;
- подтверждение опасных действий: распознавание (`guardrails.check_risky`) и поток
  `/confirm` и `/reject` в диспетчере;
- команды `/queue` и `/history`;
- исправлены статусы тестовых домиков: они больше не называются «подключёнными»
  (статус `registered`), а навязанный `content-studio` заменён нейтральным
  примером-шаблоном. Второй реальный проект выберем после осмотра ваших папок;
- запуск под Windows без `cp` и `export`: PowerShell-скрипты и инструкция, токен из
  игнорируемого файла, а не из переменной окружения.

## Обновлённый план

Этап 1 (можно без вашего компьютера, уже сделано и проверено):
изоляция домиков, реестр, маршрутизатор, allowlist, границы, подтверждение опасных
действий, очередь, статусы, история, восстановление, установка под Windows.

Этап 2 (требует вашего компьютера на связи):
осмотр реальных папок агентов, список проектов с назначением, выбор двух для
подключения (без навязывания), проверка реальной передачи задачи агенту и ответа с
сохранением изоляции, включение локального движка запуска.

Этап 3 (по желанию, локальные аналоги облачных функций Jarvis):
локальные модели через Ollama, память на домик, git-операции в домике с
подтверждением, локальные триггеры событий. Всё на вашем ПК, без покупки сервера и
без подписки Jarvis.

Блокер сейчас честно один: живой осмотр папок и проверка реальной передачи задачи
требуют, чтобы ваш компьютер был на связи (сессия Claude на вашей машине). Пока он
недоступен из облака, эти шаги не выполняю и не имитирую.
